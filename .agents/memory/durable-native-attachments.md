---
name: Durable cross-platform attachments
description: Reliability rules for native and browser byte staging, multipart retries, durable queues, cleanup, and idempotency.
---

Attachments must move from temporary picker state into app-owned durable storage before the UI can report them as safely queued: document storage on native and IndexedDB Blob storage on web. Queue metadata and all parent/dependent records must commit atomically after the bytes are durable. Every network attempt, including an authentication retry, must build a fresh multipart body. A successful upload must be removed from durable queue storage before its managed bytes are deleted. Upload identity must remain stable from the immediate attempt through offline retries.

**Why:** Native picker URIs and browser File/Blob references can expire after backgrounding, reload, or restart. Multipart bodies are not safely replayable, hidden storage failures can falsely report that a file is queued, and partial parent/photo queue writes can claim a record is safe without all of its evidence. Stable identity prevents ambiguous network responses from creating duplicate rows.

**How to apply:** Use the shared attachment transport for every queued upload path. On browser photo pickers, copy bytes into IndexedDB immediately when selection returns—not later when the form is submitted—because Safari can invalidate the temporary URL while the form remains open. Expo web may expose a FormData implementation that Safari fetch sends as an empty multipart request; build web multipart uploads as explicit Blob bodies with matching boundaries and fresh wrappers per retry. Treat an installed iOS PWA and the same site in Safari as separate queue/storage containers: clearing or repairing one does not affect the other, so recovery actions must be performed in the surface showing the queued items. Track whether form state or queue metadata owns each managed attachment; transfer ownership immediately after queue commit, serialize removal against submission, and clean only the current owner's bytes. Serialize read-modify-write queue mutations, atomically persist related parent/photo metadata, propagate storage read/write failures, preserve the attachment upload ID during retries, and classify legacy metadata-only browser records for selective recovery.
